# Сквозной прогон стенда: результаты и анализ

Атаки пропущены через весь стенд (поиск → фильтр → модель → инструменты → постобработка) **с
фильтром и без**, на одной и той же модели. Меряется конечный эффект атаки — появилось ли в
ответе кодовое слово, был ли вызван внешний инструмент, утёк ли секрет или внешняя ссылка.
Воспроизводится: `scripts/experiment_endtoend.py`, снимок — `docs/endtoend_results.json`.

Модель — «наихудшая» (симулятор, исполняет любую доставленную инъекцию). Это даёт **верхнюю
оценку** успешности: если фильтр снижает ASR даже у абсолютно податливой модели, значит он режет
саму доставку атаки, а не полагается на «послушность» LLM. На реальную локальную модель
переключается флагом `--backend ollama --model …`. Обфусцированные (base64) атаки из этого прогона
исключены: симулятор их не декодирует, их эффект меряется отдельно детекцией.

## Результат (метод на правилах)

| Показатель | Без фильтра | С фильтром |
|---|---|---|
| Успешность атак (ASR) | **0.91** | **0.68** (−25 %) |
| Вызовы внешних инструментов | 305 | 265 |
| Ложные срабатывания на чистых фрагментах | — | 0.047 |
| Чистые ответы сохранены без изменений | — | 0.964 |

По видам влияния (ASR без фильтра → с фильтром):

| Вид влияния | Без фильтра | С фильтром | Снижение |
|---|---|---|---|
| Раскрытие информации | 1.00 | 0.38 | −62 % |
| Форма / внешний канал | 1.00 | 0.57 | −43 % |
| Инструкции модели | 1.00 | 0.69 | −31 % |
| Действия / инструменты | 1.00 | 0.87 | −13 % |
| Подмена задачи | 0.54 | 0.49 | −9 % |

## Выводы

1. **Фильтр снижает успешность атак даже у наихудшей модели** (0.91 → 0.68) и предотвращает часть
   вредных вызовов инструментов — почти не трогая чистый контекст (ложные 4,7 %, ответы сохранены
   на 96 %). Это ключевой результат: защита работает до модели и не зависит от её «послушности».
2. **Сильнее всего режутся раскрытие и внешний канал** (−62 и −43 %) — виды влияния, которые запрещены
   безусловно. Это прямо отвечает на самую опасную атаку из анализа (обёртка «сообщение модели»).
3. **Подмена задачи снижается слабо** — добавлен детектор «когнитивная задача не по теме в
   фактических данных» (срабатывает на «проанализируй/напиши…», но не на физических шагах
   регламентов). Он поднимает полноту на задачах-вставках (BIPIA 0.10→0.30), но тихая подмена
   в наборе SEP остаётся самым трудным случаем — это фундаментальный предел разделения
   «данные/указания» (в самой статье SEP все модели проваливаются). Полностью закрывается только
   обучаемым скорером ценой роста ложных срабатываний.
4. **Действия снижаются слабее (−13 %)**, потому что инъекции InjecAgent сформулированы как
   обычные вежливые просьбы в данных — тот же эффект «правдоподобной обёртки». Усиление —
   проверка делегирования инструментов и обучаемый скорер.

## Как прогнать на реальной модели (на своей машине)

```bash
ollama pull qwen2.5:7b-instruct
PYTHONPATH=. python scripts/experiment_endtoend.py --ext ./ext \
    --backend ollama --model qwen2.5:7b-instruct --out docs/endtoend_real.json
```
Тогда ASR отразит реальное поведение модели, а не верхнюю оценку. Критерий утечки — секретная
метка в системном промпте; критерий атаки на действия — факт вызова внешнего инструмента.
