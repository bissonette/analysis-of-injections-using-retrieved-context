# Архитектура проекта

Проект реализует **контроль полномочий retrieved-контекста** в RAG-системе: вместо бинарного
вопроса «атака или нет» для каждого retrieved-фрагмента определяется **профиль допустимого
влияния** (какие классы поведения модели П2–П6 фрагмент имеет право менять), и фрагмент,
выходящий за границы делегированных ему полномочий, блокируется или очищается до передачи в LLM.

## Стенд (компоненты модели угроз К1–К14)

```
запрос ─▶ К2 оркестратор
             │
   К7 ретривер+реранкер ──▶ К8 КОНТРОЛЬ ПОЛНОМОЧИЙ ──▶ К3 промпт ─▶ К9 LLM ─▶ К11 постобработка ─▶ ответ
        ▲ (К5 чанкинг,                 │                                 │
         К6 индекс)                    ▼                                 ▼
                                  К12 журнал                        К10 инструменты
```

| Компонент | Модуль | Назначение |
|---|---|---|
| К2 оркестратор | `ctxauth/rag/orchestrator.py` | собирает конвейер, исполняет запрос |
| К3 системный промпт | `ctxauth/rag/prompts.py` | промпт + секретная метка (критерий утечки) + spotlighting |
| К5 чанкинг/эмбеддинг | `ctxauth/rag/chunking.py`, `embed.py` | разбиение документов, TF-IDF или sentence-transformers |
| К6 индекс | `ctxauth/rag/index.py` | векторное хранилище, косинусная близость |
| К7 ретривер | `ctxauth/rag/retriever.py` | поиск top-k, опциональный лексический реранк |
| **К8 контроль полномочий** | **`ctxauth/authority/`** | **предмет разработки — см. ниже** |
| К9 LLM | `ctxauth/rag/llm.py` | офлайн-заглушка или локальная модель (OpenAI-совместимый API) |
| К10 инструменты | `ctxauth/rag/tools.py` | регистратор вызовов (вызов = критерий атаки на П5) |
| К11 постобработка | `ctxauth/rag/postprocess.py` | блокировка внешних ссылок вне allowlist |
| К12 журнал | `ctxauth/rag/audit.py` | JSONL-журнал решений |
| К13 администрирование | `ctxauth/cli.py` | командная строка |

## Модуль К8 — контроль полномочий контекста

Четыре шага для каждого фрагмента (`ctxauth/authority/controller.py`):

1. **Делегированный профиль по запросу** (`intent.py`): запрос пользователя классифицируется
   в намерение (summarize / qa / follow_procedure / format_by_doc / …), каждому намерению
   соответствует набор полномочий, которые пользователь **делегирует** контексту.
   П3 (инструкции модели) и П4 (раскрытие) не делегируются никогда.
   Это реализация угрозы **УБИ-С14**: профиль зависит от запроса — один фрагмент легитимен
   для «выполни процедуру» и недопустим для «перескажи».

2. **Профиль заявляемого влияния фрагмента** (`rules.py` + `analyzer.py`): для каждого
   предложения оценивается, на какие полномочия П2–П6 оно претендует. Признаки:
   адресация к модели, переопределение правил, подмена задачи, запрос раскрытия, инициирование
   действий, навязывание формы/внешнего канала. Ослабляющие признаки (борьба с ложными
   срабатываниями): предостережения («never share…»), обезличенные шаги регламента,
   повествование в прошедшем времени, цитирование. Опционально — обучаемый скорер (`ml.py`).

3. **Нарушения**: полномочие заявлено (score ≥ порога) и не делегировано запросом; либо
   делегировано, но инструмент вне `tool_scope` / ссылка вне `domain_allowlist`.

4. **Решение**: PASS / SANITIZE (вырезать нарушающие предложения) / BLOCK (целиком).
   Скрытый/обфусцированный текст (ТК9) и распределённые по чанкам инъекции (ТК10) обрабатываются
   отдельно: деобфускация в `text.py`, межчанковый анализ в `controller.py`.

**Решение принимается без вердикта «атака/не атака»** — только по факту превышения полномочий.

## Соответствие таксономии модели угроз

`ctxauth/taxonomy.py`: связь ТК1–ТК10 ↔ нарушаемое полномочие (основа разметки датасета),
УБИ-С ↔ полномочия, К1–К14 ↔ модули. Таблица УБИ-С↔П — рабочая, сверяется с текстом модели угроз.

## Оценка (`ctxauth/eval/`)

Единый интерфейс `BaseDefense.filter() → FilterResult` для метода и baseline'ов
(`no_filter`, `keyword`, `binary_clf`). Метрики: Precision/Recall/F1, FPR, ASR до/после,
доля удалённого чистого контекста, задержка; разрезы по полномочию, технике, источнику.
Загрузчики бенчмарков (`ctxauth/data/loaders.py`) приводят внешние наборы к единому
`AttackSample` с разметкой по полномочиям.
